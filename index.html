OpenCrawling® is a high-performance enterprise data ingestion and security mapping framework. Powered by Java 25 and Spring Boot 4, it orchestrates secure pipelines using Apache Tika for text extraction, Apache Kafka for queueing, Apache Ozone & S3 for distributed payload storage, Redis for caching, and Ollama for embeddings while preserving document permissions (ACLs).

Designed for Enterprise Security & Scale

Going far beyond simple scraping, OpenCrawling bridges data stores and vector indexes securely.

Enterprise Security First

Built-in authority translation and Access Control List (ACL) mapping. Search engines only return documents that users are explicitly authorized to view.

High Performance & Concurrency

Leverages Java 25 Virtual Threads and Spring Boot. Processes thousands of streams with minimal memory overhead, preventing source system bottlenecks.

AI & RAG Ready Ingestion

Advanced RAG support with flexible chunking and embedding logic. Configure multiple embedding strategies (Ollama, OpenAI, HuggingFace) across diverse vector index backends.

Pluggable SPI Architecture

Simple interfaces for writing custom connectors. Define a new Repository Source, Transformation filter, or Database Output connector in just a few lines of Java.

AI-Powered Observability (AIOps)

Integrates OpenTelemetry (OTel) correlated traces and Micrometer metrics. Automatically translates complex pipeline stack traces into human-readable AI Root Cause Analysis (RCA) and diagnostic recommendations. Learn more →

Auto-Narrativization Copilot

Configured per job or interactive panel. Translates connector schemas into human-readable Mustache narrative templates and mock datasets via Ollama (llama3.2) or OpenAI. Automatically falls back to deterministic generation when AI is offline.

Java Client SDK (`oc-java-client-sdk`)

Strongly typed, fluent Java 25 & Spring Boot 4 client SDK. Programmatically manage ingestion job lifecycles, connector setups, Copilot templates, and AIOps diagnostics with zero third-party HTTP transport bloat. Explore SDK →

Enterprise Migration Mode (Apache Ozone & Amazon S3)

Run high-throughput bulk content migrations with bit-for-bit fidelity directly into Apache Ozone and Amazon S3. Bypasses text extraction, narrativization, chunking, and vector embedding to maximize transfer rates, generating Open Ingestion Standard (OIS) Zero-Trust metadata sidecars (.ois.json) with SHA-256 hashes, source ACLs, and multi-vendor storage presets.

Secure Model Context Protocol (MCP) Server

Built with Spring AI 2.0.2 over Streamable HTTP (/mcp) and SSE (/mcp/sse). Employs the pluggable McpVectorSearchBackend SPI across all 10 target vector & search engines (PostgreSQL/pgvector, Vespa, Qdrant, Milvus, Elasticsearch 8.x/9.x, OpenSearch 2.x/3.x, Apache Solr, Luxir, and Hyland OpenArch). Server-side McpAclEvaluator authoritatively evaluates Zero-Trust document ACLs with explicit deny precedence, dynamic role mapping, and integrated AIOps observability tools. Explore MCP Server →

Getting Started in 2 Minutes

Follow these quick steps to deploy OpenCrawling locally, integrate via Maven, or scaffold custom connectors with the official Maven Archetypes.

# Option 1: Standard Multi-Tier Stack (Backend + Standalone Frontend)
# 1. Start backing services (Postgres, Redis, Kafka, Ollama)
docker compose up -d
# 2. Start pre-built applications from Docker Hub (no compilation)
docker compose -f docker-compose-apps-dockerhub.yml up -d
# 3. (Alternative) Or build from source and run:
docker compose -f docker-compose-apps.yml build
docker compose -f docker-compose-apps.yml up -d

# Option 2: Decoupled Microservices Pipeline (Fully Distributed Workers)
# 1. Run using pre-built Docker Hub images (includes OTel stack)
docker compose -f docker-compose-decoupled-dockerhub.yml up -d
# 2. (Alternative) Or run using pre-built GHCR release images:
docker compose -f docker-compose-decoupled-dist.yml up -d
# 3. (Alternative) Or build from local source and run:
docker compose -f docker-compose-decoupled.yml build
docker compose -f docker-compose-decoupled.yml up -d

# Access points:
# - Standalone Administration Console: http://localhost:3000
# - Secure MCP Server / REST Backend:  http://localhost:8080
# Scaffold a ready-to-build custom connector with tests, Docker Compose overlay & Admin UI integration
# Available archetypes under org.opencrawling.archetypes:
#   1. opencrawling-archetype-repository-connector      (Ingestion sources: CMS, APIs, DBs)
#   2. opencrawling-archetype-output-connector          (Vector stores, Search engines, Sinks)
#   3. opencrawling-archetype-transformation-connector  (Custom chunking, enrichment, redaction)

mvn archetype:generate \
  -DarchetypeGroupId=org.opencrawling.archetypes \
  -DarchetypeArtifactId=opencrawling-archetype-repository-connector \
  -DarchetypeVersion=1.0.4 \
  -DgroupId=com.mycompany.connectors \
  -DartifactId=my-repository-connector \
  -Dversion=1.0.4 \
  -DconnectorName=SampleRepositoryConnector

# Build, run unit & Failsafe integration tests (*Test.java & *IT.java), and launch with Docker overlay:
cd my-repository-connector
mvn clean package
docker compose -f docker/docker-compose.dist.yml -f docker/docker-compose.override.yml up -d
mvn verify
<!-- Add core connector API to your Spring Boot application -->
<dependency>
    <groupId>org.opencrawling</groupId>
    <artifactId>oc-core</artifactId>
    <version>1.0.4</version>
</dependency>

<!-- Include FileSystem Repository Connector if required -->
<dependency>
    <groupId>org.opencrawling</groupId>
    <artifactId>oc-filesystem-repository-connector</artifactId>
    <version>1.0.4</version>
</dependency>
// Tip: Scaffold this project automatically using the Maven Archetypes tab!
// Implements RepositoryConnector (or OutputConnector / TransformationConnector) SPI
@Component
public class SampleRepositoryConnector implements RepositoryConnector {

    private final SampleRepositoryConnectorConfiguration configuration;
    private final SampleRepositoryConnectorFetcher fetcher;
    private boolean connected = false;

    @Override
    public String getName() {
        return "SampleRepositoryConnector";
    }

    @Override
    public void connect() throws Exception {
        // Initialize authenticated client session with target repository
        this.connected = true;
    }

    @Override
    public Flux<RepositoryDocument> scan(String basePath) {
        // Stream documents reactively with metadata and Zero-Trust ACLs
        return fetcher.fetchDocuments(basePath);
    }

    @Override
    public ConnectorSchema getSchema(String basePath) {
        return new ConnectorSchema(List.of());
    }
}

Open Ingestion Standard (OIS)

A vendor-neutral specification for Zero-Trust AI/RAG ingestion, Cloud Lakehouse sidecar migration (.ois.json), and agentic data logistics.

The Ingestion & Migration Manifesto

Enterprise data pipelines suffer from proprietary lock-in, unredacted PII in embeddings, and access-control leaks. The OIS specification standardizes streaming document payloads and persistent Cloud/Lakehouse Sidecar Envelopes (<key>.ois.json) with SHA-256 integrity—now featuring normative FAIL_CLOSED Security & ReBAC tuples, in-flight Pre-Embedding PII Governance (ALLOW, REDACT, DROP), Agentic Job Triggers with OAuth 2.0 RFC 8693 Delegated Provenance (onBehalfOf / actorAgent), real-time BPMN 2.0 Transition Events, and UPSERT & DELETE tombstones across SharePoint Online, M-Files, Documentum, Hyland OpenArch, Doxis, CMIS, and Apache Ozone / S3.

🔒 Fail-Closed ACL & ReBAC 📦 .ois.json Cloud Sidecars 🤖 Agentic Triggers & RFC 8693 🛡️ Pre-Embedding PII Gate ⚡ BPMN Real-Time Events 🗑️ Tombstones & Deletion 🌐 SharePoint, M-Files & Documentum 🟣 Hyland OpenArch & Doxis 🏛️ OASIS TC Proposal
