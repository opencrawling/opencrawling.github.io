OpenCrawling 1.0.4 Released: The First Official General Availability Milestone for Enterprise AI & Search Ingestion

Today marks a monumental milestone for open-source enterprise intelligence: we are proud to announce the first official general availability release: OpenCrawling 1.0.4! Engineered from the ground up on Java 25 (Virtual Threads / Project Loom), Spring Boot 4.1.1, and the Open Ingestion Standard (OIS), version 1.0.4 brings a unified, crash-resilient, Zero-Trust pipeline bridging siloed enterprise repositories directly to AI vector stores, search clusters, and LLM agent frameworks without compromising document access controls.

01 The Enterprise AI Ingestion Crisis & The OpenCrawling Mission

Across enterprises worldwide, AI initiatives face an urgent bottleneck. While large language models (LLMs) and vector retrieval technologies have matured rapidly, the data pipelines feeding them remain fragile, fragmented, and insecure. Enterprise knowledge is trapped across heterogeneous repositories—ranging from modern Microsoft SharePoint Online libraries and M-Files vaults, to legacy ECM platforms like Alfresco, Doxis, and CMIS archives, relational databases, and Apache Iceberg analytical data lakes.

Existing ingestion tools force enterprises into an unacceptable compromise: either write brittle, proprietary point-to-point scripts that drop security permissions, or run monolithic crawlers that collapse under multi-gigabyte files and leak restricted intellectual property into vector indexes where any employee or LLM agent can retrieve it.

OpenCrawling was born to solve this crisis. Guided by the vendor-neutral Open Ingestion Standard (OIS), OpenCrawling establishes a modern, distributed, memory-safe ingestion engine. It treats Access Control Lists (ACLs) as immutable, first-class citizens, decouples heavy binary parsing from vector generation, and delivers native LLM integration through the Model Context Protocol (MCP).

✅

First Official GA Release: OpenCrawling 1.0.4 represents the stabilization of the core API, complete multi-service Docker Compose topologies, self-contained Distribution ZIP packages for Bare-Metal and VM environments, a standalone CLI with Homebrew distribution, and comprehensive integration testing across enterprise repositories.

1. Java 25 & Virtual Threads (Project Loom) Everywhere

OpenCrawling leverages Java 25 Virtual Threads throughout the entire runtime. Instead of managing complex reactive callback chains or risking operating system thread exhaustion under heavy I/O, every document fetch, HTTP request, database call, and vector transmission runs on a dedicated virtual thread. Using structured concurrency scopes (StructuredTaskScope), crawlers achieve tens of thousands of concurrent operations with negligible memory overhead and native stack traces.

2. Isolated Apache Tika 4 Text Extraction via PipesForkParser

Extracting text from arbitrary enterprise binaries (corrupted PDFs, complex DOCX documents, macro-enabled spreadsheets, massive compressed archives) has historically been the primary cause of crawler crashes due to memory leaks, native library segfaults, or CPU infinite loops.

In OpenCrawling 1.0.4, document parsing is completely isolated using Apache Tika 4's PipesForkParser. Each parsing task executes in a sandboxed, memory-bounded child JVM process governed by strict timeouts. If a malicious or poisoned document triggers an out-of-memory error or process crash, only the ephemeral child process terminates—the parent ingestion service logs the error, emits an audit event, and continues processing without downtime.

3. Claim-Check Pattern with Redis Stack & Apache Ozone

Message brokers are optimized for high-volume, low-latency streaming—not multi-megabyte binary payloads. OpenCrawling implements the Claim-Check Pattern:

  • When a repository connector discovers a binary payload, the raw bytes are streamed directly into an enterprise object store (Apache Ozone S3 / Native RPC or Redis Stack).
  • A lightweight OIS Claim-Check Token containing payload reference URIs, SHA-256 integrity digests, and metadata is published to Apache Kafka.
  • Downstream consumer workers retrieve the binary payload on-demand only when extraction is executed, keeping Kafka topic throughput blazing fast and broker memory lean.

04 Zero-Trust Security & The Model Context Protocol (MCP)

The most perilous vulnerability in enterprise AI deployments is knowledge leakage. When internal documents are converted to vector embeddings and stored in a shared database without authorization controls, any employee or AI agent querying the index can access confidential financial reports, executive memos, or HR records.

OpenCrawling enforces a strict Fail-Closed Zero-Trust Architecture:

  1. Lossless ACL Ingestion: Every connector captures fine-grained access control lists—explicit users, Active Directory / Entra ID security groups, and inheritance flags—and normalizes them into the OIS security schema.
  2. Deterministic Chunk Lineage: Document chunks inherit parent document permissions with deterministic, hash-based chunk IDs, ensuring that updates or deletions at the source automatically invalidate downstream vector chunks.
  3. Universal Secure MCP Server (oc-mcp-server): OpenCrawling embeds a native Model Context Protocol server exposing tools such as secure_vector_search, openarch_search, and openarch_fetch_document directly to LLM environments like Claude Desktop, Cursor, ChatGPT, and enterprise autonomous agents.
// Example: OpenCrawling Zero-Trust OIS Document Manifest
{
  "oisVersion": "1.0.0",
  "documentId": "sp-sec-2026-audit-report",
  "sourceUri": "https://company.sharepoint.com/sites/legal/Audits/2026.pdf",
  "title": "Confidential Security Audit Report 2026",
  "mimeType": "application/pdf",
  "security": {
    "inheritanceEnabled": false,
    "allowEntities": [
      "user:auditor@company.com",
      "group:SECURITY_COMPLIANCE_DIRECTORS"
    ],
    "denyEntities": [
      "group:EXTERNAL_CONTRACTORS"
    ]
  },
  "metadata": {
    "classification": "TOP_SECRET",
    "retentionYears": 7
  }
}

When an AI agent invokes secure_vector_search, the MCP server evaluates the caller's verified identity tokens against the stored ACLs before returning candidate chunks. If the caller lacks authorization, the chunk is filtered out at the vector database level—it is never passed into the LLM context.

05 Developer & Operator Experience

OpenCrawling 1.0.4 delivers a developer experience designed for rapid adoption, straightforward automation, and effortless day-2 operations:

1. OpenAPI 3.1 & Embedded Swagger UI

Full OpenAPI 3.1 specification compliance with rich interactive documentation available out-of-the-box at http://localhost:8080/swagger-ui.html. Explore endpoints, test crawler job dispatches, introspect connector configurations, and generate SDK clients in any programming language.

2. OpenCrawling CLI (oc-cli) & Homebrew Tap

Operators can control OpenCrawling from the terminal, bastion hosts, or CI/CD pipelines using our Picocli-powered CLI. Install it instantly on macOS and Linux via our official Homebrew tap: 

# Install OpenCrawling CLI via Homebrew
brew tap opencrawling/tap
brew install oc-cli

# Test connectivity to a repository connector
oc connector test SharePoint_Online

# Start an on-demand crawl job
oc crawl start SharePoint_Online

# Inspect cluster health and active workers
oc status

3. Official Java Client SDK & Maven Connector Archetypes

Developers building custom integrations can take advantage of the official Java Client SDK (oc-java-client-sdk), which provides type-safe clients for managing crawler jobs and submitting OIS documents.

To create custom plugins, developers can generate complete, production-ready Maven projects in seconds using our official archetypes: 

mvn archetype:generate \
  -DarchetypeGroupId=org.opencrawling \
  -DarchetypeArtifactId=opencrawling-archetype-repository-connector \
  -DarchetypeVersion=1.0.4 \
  -DgroupId=com.mycompany.ingestion \
  -DartifactId=custom-repository-connector \
  -Dversion=1.0.0-SNAPSHOT

4. Modern React 19 Admin UI & Lakehouse Audit Ledger

Version 1.0.4 includes a responsive, dark/light theme React 19 + Vite web console featuring live connectivity testing buttons, visual crawl pipeline monitoring, and credential masking.

For governance and compliance, an embedded DuckDB Lakehouse Audit Reporting engine allows operators to run SQL analytical queries directly over historical ingestion events, error rates, and security classifications without installing external data warehouses.

06 Flexible Deployment: Containers, Bare-Metal & VMs

Recognizing that many regulated enterprise environments, defense organizations, and air-gapped data centers prohibit container runtimes (Docker, Podman, Kubernetes), OpenCrawling 1.0.4 provides first-class support for both containerized and container-free environments:

Container Deployments (Docker Hub & GHCR)

Official multi-arch container images are published on Docker Hub (opencrawling/*) and GitHub Packages (ghcr.io/opencrawling/*). Spin up the complete decoupled production stack with a single command: 

# Launch full decoupled stack (Kafka, Redis, Postgres, Ollama, Runtime, Embedding, UI)
docker compose -f docker-compose-decoupled-dockerhub.yml up -d

Self-Contained Distribution ZIP Packages (Bare-Metal & VMs)

For native deployments across Linux (RHEL, Ubuntu, Debian, SLES), Windows Server, and macOS, OpenCrawling publishes 5 self-contained Distribution ZIP archives with every release:

Distribution Archive Approx. Size Target Deployment Role
opencrawling-platform-dist-1.0.4.zip ~745 MB Master bundle: All-in-One single VM or enterprise golden provisioning image.
opencrawling-runtime-dist-1.0.4.zip ~459 MB Runtime, crawler worker, ingestion consumer, and control plane nodes.
opencrawling-embedding-service-dist-1.0.4.zip ~192 MB Stateless embedding worker VMs with Spring AI vectorization models.
opencrawling-admin-ui-dist-1.0.4.zip ~275 KB Frontend static bundle for Nginx, Apache HTTP Server, or Windows IIS reverse proxies.

Every distribution archive includes native startup wrappers (.sh and .bat), production configuration templates, pre-configured systemd service units, and SHA-256 cryptographic checksums for compliance verification.
